# Веб-чат для сайта РТУ МИРЭА

Веб-чат использует тот же `rag.ask.respond()`, что и Telegram-бот. Браузер вызывает FastAPI. Приложение ищет источники через Qdrant и Ollama, а генерацию и реранкинг запрашивает у внутреннего vLLM на H100. Ключ vLLM хранится на VM приложения в `.env.campus`.

## Запуск на VM

Подготовьте индекс и проверьте кампусные сервисы по [инструкции по развёртыванию](CAMPUS.md). В каталоге действующего Compose-проекта выполните:

```bash
docker compose -p mirea-campus -f compose.campus.yml --profile web up -d --build web
curl -fsS http://127.0.0.1:8080/healthz
docker compose -p mirea-campus -f compose.campus.yml --profile web logs -f web
```

Используйте имя того же Compose-проекта, где уже работают Qdrant и Ollama. `/healthz` подтверждает, что приложение запустилось и загрузило индекс. Для сквозной проверки задайте вопрос через чат и проверьте ответ и ссылки.

Для теста через локальный HTTP можно запустить веб-сервис с `WEB_COOKIE_SECURE=0`. На HTTPS оставьте значение по умолчанию. Если порт 8080 занят, задайте `MIREA_WEB_PORT` и обновите upstream в прокси.

## Маршрут на сайте

Добавьте на сайт ссылку «Помощник абитуриента» на `/assistant/`. Пример для Nginx на той же VM. Если прокси сайта работает на другой машине, согласуйте с ИТ внутренний маршрут до VM приложения.

```nginx
location = /assistant {
    return 308 /assistant/;
}

location /assistant/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 8k;
    proxy_read_timeout 180s;
}
```

Завершающий слеш в `proxy_pass` снимает префикс `/assistant/`. Приложение получает `/`, `/static/…` и `/api/chat`. Ссылка открывает готовую страницу. Если нужен встроенный блок, тот же URL можно вставить через iframe на странице того же домена, если это разрешает политика сайта.

Для первого запуска согласуйте HTTPS и лимит запросов на публичном маршруте с администратором сайта. Например, настройте на прокси ограничение по IP для `POST /assistant/api/chat`. Лимит по cookie действует на один браузерный сеанс. Таймаут прокси проверьте на реальных запросах. Если прокси вернул таймаут, приложение может всё ещё завершать обработку запроса.

## API и параллельные запросы

| Запрос | Назначение |
|---|---|
| `POST /assistant/api/chat` с JSON `{"question":"Какие документы нужны?"}` | Возвращает `answer` и список `sources` с полями `title` и `url`. |
| `DELETE /assistant/api/chat` | Очищает историю текущего диалога и сохраняет его лимиты. |

Браузер получает случайный идентификатор диалога в cookie с `HttpOnly`, `Secure` и `SameSite=Lax` по умолчанию. В памяти процесса хранятся до 256 сессий и три пары «вопрос–ответ» на сессию. История перестаёт использоваться после 30 минут бездействия. Кампусная конфигурация отключает файловый журнал диалогов и Langfuse.

Один веб-процесс принимает до двух одновременных запросов. Третий получает `429`, а повторный запрос в активном диалоге получает `409`. Лимиты веб-чата и Telegram работают в отдельных процессах, а запросы обоих каналов попадают в общий планировщик vLLM. Проверьте задержку и очередь при одновременных обращениях из обоих каналов перед публикацией.
